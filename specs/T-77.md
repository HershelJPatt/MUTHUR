# T-77 — Diagnose catalog harnesses before agents exist

> Frozen spec. Stop and report missing decisions; do not improvise.

## Goal
Doctor warns when a tier catalog names a harness without a kit even before an agent is registered, without duplicating T-61 agent diagnostics.

## Context
Base is main at 357c6af. Read CLAUDE.md and muthur.project.json. DoctorAgentCheck already checks standing (not ConductorStaffed) agents, using ordinal comparisons. HarnessService.TiersAsync rereads the catalog and translates unreadable/invalid files to MuthurException. KitDirectory.Harnesses returns null for unavailable sources, empty for a readable empty kit. Startup registers singleton IDoctorCheck implementations. DoctorService sorts harness rows already.

## Non-goals
No registration restrictions, catalog schema/default changes, kit changes, new API/CLI surfaces, or changes to existing agent verdicts/source warnings.

## Design
Add DoctorHarnessCheck(AgentService agents, HarnessService harnesses, MuthurOptions options) implementing IDoctorCheck. Read KitDirectory.Harnesses(KitDirectory.Locate(options.KitDir)); return [] when null. Read all TiersAsync candidates; catch MuthurException and return [] (existing source diagnostics stay owned by DoctorAgentCheck). Do not swallow cancellation.
Get standing agents using the identical !ConductorStaffed predicate as DoctorAgentCheck, irrespective of status. For distinct ordinal harness names in all catalog tiers, emit a row only if absent from kits AND absent from the standing-agent harness set. Conductor-only agents must not suppress the catalog row. Deduplicate repeated candidates across tiers, accounts and models. Compare ordinally without normalization. Include limited candidates. No positive rows.
Row: category harness, subject the exact catalog harness string, status Warn; detail exactly: "Harness '<harness>' has a tier entry in harnesses.json but no kit, so a session started on it gets no procedures. Add kit/<harness>/kit.json, or correct the spelling in harnesses.json."
Register beside DoctorAgentCheck in Infrastructure/Startup.cs. No mutation, probing or network; same behavior offline and probe. Reread on each call, no cached catalog/agent/kit sets.
