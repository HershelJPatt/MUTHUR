# T-98 — Census fixture cleanup lock

> Frozen spec. Stop and report if this is wrong or incomplete.

## Goal
Remove intermittent fixture teardown failures caused by a transient Windows sharing lock, without changing census timeout or descendant termination semantics. Persistent cleanup failures must still fail the test.

## Context
Base is main 608617f. T-98 has no decisions or prerequisite tasks. T-92's recorded log reports IOException sharing violation deleting the fixture root at Dispose line 17, after the descendant timeout theory body. The lock holder is not identified, so do not claim proven descendant leakage. CensusWindowsProcess already terminates its owned job and waits for zero active processes; tests assert exit 124 and a stopped descendant. The fixture currently deletes its directory once synchronously. Eventually provides bounded condition polling (60 second hang budget, 10ms probe interval).

## Non-goals
No changes under src/, runner timeout values, process termination, assertion weakening, skipped tests, broad exception swallowing, or global cleanup policy. No new external tools or packages.

## Design
Change CensusCommandRunnerTests from IDisposable to xUnit IAsyncLifetime. InitializeAsync completes immediately. DisposeAsync awaits a private static DeleteFixtureDirectoryAsync(string path) helper in this same test class.
The helper uses Eventually.TrueAsync to attempt Directory.Delete(path, recursive: true) until successful. Treat DirectoryNotFoundException as success (idempotent cleanup). Retry only IOException with HRESULT 0x80070020 or 0x80070021 (Windows sharing/lock violations), and only on Windows. Other exceptions propagate immediately. Do not retry UnauthorizedAccessException or directory-not-empty errors without evidence. On exhausted Eventually budget, fail with a diagnostic containing the directory path and the last sharing exception as an inner exception (catch only the Eventually timeout XunitException and wrap as IOException). Do not add fixed sleeps or change Eventually.
Keep every existing runner assertion and timeout unchanged. Add a concise comment distinguishing exit assertions from observing filesystem release.
Add one CensusWindowsFact in this class exercising the helper against a real FileStream opened inside a separate child directory without FileShare.Delete. Start deletion while the stream is held; because the first probe executes synchronously, assert the cleanup task is incomplete and the directory exists. Release the stream, await cleanup with Eventually.CompletesAsync (or WaitAsync(Eventually.Budget)), and assert the directory is gone. Use try/finally or using ownership so an assertion failure always releases the stream and observes the cleanup task. Also invoke the helper again on the removed path to cover idempotence. This test must fail with the original single-delete implementation. No simulated exception-only test.
