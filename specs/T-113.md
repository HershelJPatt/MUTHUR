# T-113 — Shared capability-probe admission

## Goal and reconciled scope
Deliver the vendor-neutral admission/release seam T-100 needs, independently of its unfinished capability engine. Main at 89dc34c contains no capability probe command. Do not import worker/T-100-capabilities-v2 or depend on T-100: T-100 explicitly depends on this task. Its approved proposal preserves the two-session ceiling, account restrictions and daily limits. No simulated execution is real-use evidence.

## Context
ConductorService owns _pass and _running, and records conductor.staffing events. BudgetBlockedAsync reconstructs per-task/role rolling-day budget including authorized reset events. ## Non-goals

## Design
1. Add contracts ProbeAdmissionRequest(Task, Tier, Harness, Model, Account, RunId), ProbeAdmissionDto(ReservationId, Task, RunId), ProbeReleaseRequest(ReservationId). All IDs are nonempty strings; RunId must be a GUID in N format. Add routes POST /api/v1/workers/probes/admit and POST /api/v1/workers/probes/release. Require a registered mastermind agent owning the named in-progress task, or Founder. Owner authorization is checked using current ledger state, not a supplied name. Release is restricted to the original caller identity (or Founder), even after task ownership changes.
2. Implement admission methods on ConductorService, splitting into a partial file ProbeAdmission.cs if useful. Reuse its _pass semaphore: acquire it for the entire admission operation so conductor staffing and external admission cannot race. Under that gate, a Ledger.MutateAsync checks task ownership, current account limit and exact currently configured tier candidate identity. Reject absent candidates or limited accounts; do not create catalog entries. Reuse HarnessService catalog parsing through an internal method accepting the current db/now if needed. Unknown/off conductor or cancellation/shutdown refuses new admissions. An admitted probe consumes ONE additional slot; its orchestrator is still counted. Do not replace or borrow its parent's slot.
3. Persist reservations as ledger events, not a migration: worker.probe_admitted includes reservationId, runId, owner agent ID/name, tier, harness, model, account, role '#orchestrator'. worker.probe_released identifies the reservation. Replay these events for active reservations. No TTL auto-reclamation: elapsed time is not proof a process died. Active reservations survive restart and remain charged until an authorized release after process cleanup. A release of an already released owned ID succeeds without another event; unknown ID is not_found. Same owner/runId/identical request admission is idempotent and returns the original reservation without another charge, including after release (never reactivates it). Reuse of a run ID with different inputs fails probe_run_conflict. Cross-owner collisions never disclose or grant a reservation.
4. Capacity equals active conductor _running plus active external reservations. RunPassAsync subtracts active reservations from its effective ceiling under _pass before ANY overseer/validator/orchestrator start. Admission checks the same current CeilingAsync result (never increases it). Status must include active reservations in Running and Sessions using role '#capability-probe:<reservationId>'; maintain Running == Sessions.Count. Persist-before-return; failed ledger commits leave no phantom slot. In-flight release cannot cause over-admission. Admission while stop is in progress must fail closed.
5. Daily budget: count worker.probe_admitted as attempts in the SAME task/#orchestrator bucket as conductor.staffing. Extend BudgetBlockedAsync event replay preserving all existing reset behavior exactly. Admission checks that bucket before recording the attempt. Released, cancelled and failed probes remain attempts; repeated retries of identical run IDs are not attempts. No separate probe-only budget or automatic reset. Existing account limits are checked in the admission mutation.
6. Stable refusals: probe_capacity_exhausted, probe_budget_exhausted, probe_account_limited, probe_candidate_unavailable, probe_admission_disabled, probe_run_conflict (rule violations except conflict as appropriate); unauthorized uses existing auth failure. Validate malformed inputs before side effects.
7. Add launch-side generic ProbeReservationRunner with an interface IProbeAdmissionClient exposing AdmitAsync and ReleaseAsync, DTOs or neutral parameter records as appropriate. Its RunAsync accepts the admission request and a Func<CancellationToken, Task<T>> callback. Obtain admission before calling callback, refuse without callback if admission fails. Execute once, never retry/fallback automatically. Always release in finally AFTER callback has finished cleanup, using a separate bounded cancellation token (10 seconds) unaffected by the cancelled caller. Failure to release must surface with reservation ID for idempotent recovery and must not silently claim cleanup; preserve the original callback failure in an AggregateException if both fail. Document callback contract: bounded execution and process-tree cleanup completed before returning. This wrapper does not implement a probe or authorize arbitrary commands. The HTTP adapter belongs in CLI and uses HubClient/source-generated JSON; expose internal adapter as needed for tests. Production capability probing remains absent/fail-closed until T-100 wires this contract.
8. Recovery is explicit: retain durable reservation on uncertain cleanup; original owner can retry release after confirming callback/process cleanup. Do not auto-clear at restart, elapsed TTL, task completion, or lease expiry. Describe this limitation and the integration obligation in docs/T-113-probe-admission.md; no claim that hard-crash cleanup is demonstrated.
