# T-82 — Report unreadable kit sources truthfully

> Frozen spec. If a requirement is wrong or missing, stop and report; do not improvise.

## Goal
A kit source held by another process is refused before writes, with the actual source path, an ordinary read-failure diagnosis, and an explicit unchanged/retry assurance. Preserve exit 2 and invalid_manifest.

## Context
Base: main at 6e60e42, including landed T-55 transactional installer. Task branch: task/T-82-manifest-io. Check git log and ancestry before work. src/Muthur.Cli/Commands/KitCommands.cs separates TryReadManifest validation from InstallTransaction. TryReadEntry reads source text for include tokens without an I/O catch. The last-resort catch incorrectly attributes every exception to a reader defect. tests/Muthur.Cli.Tests/KitManifestTests.cs contains CLI capture helpers and a fallback guard test. Follow CLAUDE.md and KitEnvironment serialization.

## Non-goals
No changes to write-phase transactions, exit codes, JSON schema, manifest validation ordering, include expansion, automatic retries, or hub behavior. No dependencies on unlanded work. No local-implementer delegation.

## Design
1. In TryReadEntry, isolate File.ReadAllText(source) immediately before IncludePattern matching in a try/catch filtered to IOException or UnauthorizedAccessException. On failure set problem to `${source} could not be read while validating ${manifestPath}: ${exception type}: ${exception message}. The repository was not changed. It is safe to re-run the command after resolving the read failure.` Return false. Match tokens against the successfully read string. Do not infer locking from localized exception text. Source must be the leading full resolved path, not merely appear within the OS message.
2. Give the existing ReadManifest manifest-file I/O catch the same final two sentences and exception type, preserving its `${manifestPath} could not be read: ` prefix.
3. Keep the last-resort broad guard, clear entries, and use `${manifestPath} could not be validated: ${exception type}: ${exception message}. The repository was not changed.` Do not assert defect, blame the manifest, request a report, or claim to know the actual failing file. Update its comments and existing test accordingly.
4. Keep existing specific rule diagnostics unchanged. Validation must complete before any writes, including earlier valid entries and installer-owned files.
