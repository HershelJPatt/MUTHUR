> Frozen spec. An implementer completes this without making design decisions.

## Goal

Make a misplaced Claude worktree loud before it builds: the implementer and specialist must validate the named task branch, dispatched commit, clean tree and committed spec, reconcile only under the existing safe recovery rules, then verify the result. Missing or changed inputs produce STATUS: blocked and no product edits.

## Context

## Design

1. Add dispatch inputs to core implementer's What you get: named local base branch, full commit SHA at dispatch, and named default branch. Both Claude agent descriptions and orchestration reminder must request all of them.
2. Before any ancestry tests, resets or spec reads, require git commands to succeed: git show-ref --verify refs/heads/<base>; git rev-parse --verify refs/heads/<base>^{commit}; git rev-parse --verify HEAD^{commit}. Compare resolved base with supplied dispatch SHA. Missing input, failed resolution, or a moved base must return STATUS: blocked with expected branch/SHA and observed HEAD/base (or missing) in BASE/NOTES; no edits, reset, merge, rebase or fallback to another checkout. A SHA complements the live branch; it does not replace it. Orchestrator redispatches with an updated frozen assignment if base moved.
3. Check git status --porcelain succeeds and is empty before reconciliation. Verify spec exists as a committed blob via git cat-file -t refs/heads/<base>:<spec path> (must be blob). Missing spec or failed Git command blocks. Quote argument examples that contain braces/colons and explain substituting placeholders; avoid shell-specific claims of portability.
4. Preserve existing guarded recovery and resumed-work logic. Make explicit: git merge-base exit 0 means ancestor, 1 means not ancestor, any other code blocks (never treat a Git error as permission to reset). Resolve default branch successfully before using its containment test. After either allowed reset, require command success, HEAD equal to the resolved base SHA, base still equal dispatch SHA, and clean status; otherwise blocked. For matching initial HEAD, still verify clean state/spec. Resumed work keeps existing rule (not required to have HEAD equal base), but still checks base did not move and reads committed spec from that verified base. Never recover a spec alone with git cat-file/show while continuing to build an unreconciled wrong lineage.
5. After reconciliation and immediately before reading spec, re-resolve named base and require it still matches dispatch SHA; git show refs/heads/<base>:<spec path> must succeed. Reports identify dispatch SHA, initial HEAD, resulting HEAD, and any recovery; blocked reports enough to diagnose missing refs/spec or moved base. Preserve STATUS vocabulary.
6. Claude orchestrate documents that MUTHUR does not select the native Agent worktree start point, and shows the explicit fallback: muthur worker run --tier implementer --spec specs/T-n.md --unit "<unit>" --task T-n --base task/T-n-<slug>. Include base branch, dispatch SHA, default branch in its --note example because current WorkerPrompt does not automatically supply these. Do not promise worker run fixes arbitrary dirty/divergent worktrees; it creates a fresh one.
