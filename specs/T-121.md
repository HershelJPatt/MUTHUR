## Design

### Wire contract and durable ownership

Add separate full-worker contracts in src/Muthur.Contracts/WorkerAdmission.cs, register every wire DTO in MuthurJsonContext and add Routes constants and HarnessEndpoints mappings:

- POST /api/v1/workers/admit: WorkerAdmissionRequest(Task, Tier, Harness, Model, Account, RunId, InputHash). Strings are required; RunId is GUID N, InputHash is lowercase SHA-256 hex. Return WorkerAdmissionDto(ReservationId, Task, RunId, MayExecute).
- POST /api/v1/workers/release: WorkerReleaseRequest(ReservationId, CleanupConfirmed). CleanupConfirmed must be true; it is an explicit caller attestation, never inferred by elapsed time or status.
- GET /api/v1/workers/reservations: return the caller's active reservations (Founder may list all), including reservation ID, task, candidate, run ID, input hash and admission timestamp. Do not expose credentials.

Implement admission/release in src/Muthur.Server/Services/WorkerAdmission.cs as a ConductorService partial. Reconstruct records from worker.admitted / worker.released ledger events, including immutable original owner identity. Use Ledger.MutateAsync under _pass for checking and recording. Do not add a separate scheduling lock. Every state mutation records its event in the same transaction.

Admit only a registered mastermind owning the in-progress task, or Founder. Resolve replay ownership first after validating field syntax: a previous run owned by a different identity is unauthorized; changed inputs yield HTTP 409 worker_run_conflict; identical owner/run/input returns the original ID and MayExecute=false, including after release or task ownership change. Only a newly committed admission returns true. A lost first response grants no execution permission; there is no automatic admission retry or replay release. Namespace worker run IDs separately from probe IDs.

For a new reservation, validate current task ownership/state, conductor enabled/not stopping, exact tier/candidate catalog membership, account availability, ceiling, and the existing rolling daily #orchestrator task budget. Apply the existing account comparison and TimeProvider semantics. Inside the same critical section, occupied capacity equals existing RunningCount plus active probe reservations plus active full-worker reservations. A parent slot is never lent to its child. Apply that total in conductor/overseer staffing, probe admission, full-worker admission and status. Preserve daily reset triggers; include worker.admitted exactly once in BudgetBlockedAsync. Neither release nor worker run reports refund or charge an attempt. Denials create no admitted event and consume no budget.

Use HTTP 422 codes worker_request_invalid, worker_admission_disabled, worker_candidate_unavailable, worker_account_limited, worker_capacity_exhausted, worker_budget_exhausted; preserve unauthorized and not_found conventions. Admission transport errors, missing endpoints, malformed replies and unsupported versions stop dispatch without side effects. Release is allowed only to original owner or Founder, even after task reassignment. Releasing an already released owned record is idempotent with no second event. False/missing cleanup attestation yields worker_cleanup_unconfirmed. Never auto-release on restart, task transition, claim expiry, timeout or daily reset. Status lists #full-worker:<reservationId> separately from probes.

### Attempt boundaries and binding

Implement IWorkerAdmissionClient and a CLI HubClient adapter in src/Muthur.Cli/Infrastructure/WorkerAdmissionClient.cs. Move first worktree/scratch creation into the first successfully admitted attempt's scope. Read-only base/spec/candidate eligibility checks may precede admission; neither capability probing nor any model execution may be hidden in those checks. Preserve existing capability selection and mismatch reporting.

Task identity is required for full-worker dispatch, including legacy specs without capabilities. Missing --task fails worker_request_invalid before worktree creation. Existing specs need no new capability declaration. Unsupported harnesses, unavailable executables and static capability mismatches skipped before admission consume no slot or budget and report Started=false.

For every eligible candidate generate one immutable run ID before admission and carry it unchanged through SessionWorkspace, admission, WorkerAttempt and WorkerRunReport. InputHash is SHA-256 over UTF-8 JSON produced in fixed property order using Utf8JsonWriter (no indentation): task, tier, harness, model, account, repository absolute path, base commit, spec blob, spec path, unit (null preserved), parent run (null preserved), branch, worktree absolute path, timeout ticks, complete composed prompt, ordered allowed commands, ordered capability requirements. Do not hash credentials or volatile timestamps. Canonicalize absolute paths with Path.GetFullPath; preserve all remaining string bytes. Freeze the values used to create the actual request; do not reread mutable spec/project files after admission.

Each fallback attempt must obtain its own reservation and one daily charge. Release a completed attempt only after its process tree is confirmed gone; then check the next candidate afresh. A rate-limit outcome may trigger fallback after release and the existing account update. Admission denial, replay, uncertain cleanup or release failure terminates the dispatch; it does not try a different candidate to bypass the gate. No interval may contain two child attempts under one reservation. Reuse a successfully created worker worktree for sequential fallback; creating it belongs to the first attempt and requires that attempt's reservation. An admitted attempt consumes its daily unit even if cancelled before launch, worktree creation fails or process start fails. This conservatively counts reserved opportunities, while FullStarts counts actual successful process starts only.

Catch cancellation across all admitted setup/launch paths. If no process started and all setup subprocesses are confirmed gone, release. Keep no model process alive during launcher commit/report operations. Ordinary worktree retention for review remains supported; reservation lifetime follows processes, not a retained directory. Reports include every attempt's reservation ID, run ID, Started, failure kind and cleanup status; do not report successful implementation for admission/release/cleanup errors.

### Process lifetime and recovery

Introduce a worker-specific process containment seam in src/Muthur.Launch/WorkerProcessRunner.cs with a typed result distinguishing NotStarted, ExitedAndTreeEmpty and CleanupUncertain. WorkerLauncher must use it for full-worker execution; generic ProcessResult.Ok is not cleanup proof. On Windows use a job object with kill-on-job-close and no breakaway: launch suspended, assign before resuming, then monitor job active-process count. Redirect/drain output and handle stdin inside the same try/finally lifetime. On cancellation/timeout terminate the job and wait with a separate ten-second cleanup deadline. Only an observed empty job (or proven no process creation) allows release. If assignment, observation or cleanup cannot be established, retain the reservation and report CleanupUncertain. Unsupported containment platforms fail closed before process creation; do not silently downgrade to process.Kill. Test the containment policy behind an injectable interface and exercise Windows containment with a synthetic child/grandchild process. Never pass hub identity/token to a worker.

Use a separate ten-second cancellation budget for release. Preserve both execution and release failures. On hard CLI/hub crash, the durable reservation remains occupied; kill-on-job-close limits process survival but does not automatically free admission. Return the reservation ID in every recoverable error. Add worker reservations and worker release <id> --cleanup-confirmed commands to inspect and explicitly recover after owner/Founder establishes that the process tree is gone. The CLI must require the flag; neither it nor the hub guesses cleanup from a missing PID. A retry of release is allowed; retrying execution under an old admission is not.
