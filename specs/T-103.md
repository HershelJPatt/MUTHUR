## Design

### Persisted records

Use three new entities/tables with EF migration and model snapshot. Incident: integer ID shown as I-n; ProjectId; Title; State (suspected, confirmed, mitigated, resolved, disproven); Signature; ExecutionPath; Configuration; ConditionVersion (starts 1); Diagnosis; Workaround; AuthorizationReference; RecoveryCondition; CreatedAt/UpdatedAt. All strings use ordinal exact comparisons after trimming. Signature, path and configuration are opaque observed identifiers, not interpreted by the hub. Incident observation: integer ID; IncidentId; TaskId; optional RunId string; Evidence string; Signature/ExecutionPath/Configuration snapshots; ConditionVersion; CreatedAt; Actor; Active (true initially); UnlinkReason. Append-only observations except attributable unlink, retaining all historical fields. Suppression: IncidentId, TaskId, Assignment (literal #orchestrator or an existing validator role key); ConditionVersion; EvidenceObservationId; Reason; CreatedAt; Active; ReleasedAt; ReleaseReason. One active suppression per incident/task/assignment/version. FK delete Restrict; no delete API.

Use injected clock/Ledger time and normal Caller.RequireIdentified on mutations; no founder impersonation. Restrict linking/suppression/unlink to founder or current task owner; unowned tasks may be linked by identified agents, matching dependency operation policy. Incident state/diagnosis/recovery updates require identified agents (technical ledger annotations only). Do not widen overseer middleware mutation allowlist.

### Public surface

Add Contracts/Incidents.cs DTO/request records, enum wire conversions if using enum, Routes constants, source-generated JSON registrations. New IncidentService and IncidentEndpoints with registration, and IncidentCommands wired in CLI Program. Base route /api/v1/incidents.

CLI commands (hyphenated flags map to PascalCase request properties):

* `incident add <title> --project <key> --signature <text> --path <text> --configuration <text> --recovery <text>` creates suspected incident, diagnosis/workaround/authorization empty.
* `incident list [--project <key>]` lists all states ordered ID. `incident show I-n` returns incident, all observations (including inactive), all suppressions and their current effective status/reason, and incident events in sequence order.
* `incident update I-n --diagnosis <text> [--workaround <text> --authorization <reference>]` stores shared diagnosis and optional workaround. A nonempty workaround requires a nonempty authorization reference. Stores annotations only, never grants capabilities. Omitted optional values preserve existing ones.
* `incident transition I-n --state <state> --evidence <text>` allowed transitions: suspected -> confirmed/disproven; confirmed -> mitigated/resolved/disproven; mitigated -> confirmed/resolved/disproven; resolved/disproven -> suspected. No self transition. All require evidence. Reopening increments ConditionVersion and leaves historical links/suppressions ineffective. Terminal transitions release incident suppressions with event/evidence but never alter tasks.
* `incident observe I-n --task T-n --evidence <text> --signature <text> --path <text> --configuration <text> [--run <id>]` appends independent observation in same project. Observations need not match incident signature/path/config: retaining differing evidence is useful. Record current condition version. Never silently auto-link or suppress from matching alone.
* `incident unlink I-n --observation <id> --reason <text>` marks observation inactive; releases only suppressions backed by this observation; retain historical evidence and record correction. Repeat unlink is a no-op, no extra event.
* `incident match --project <key> --signature <text> --path <text> --configuration <text>` GET /matches with escaped query params; read-only returns potential matches with exactly equal tuple and state suspected/confirmed/mitigated, including shared diagnosis/workaround and recovery condition, explicitly advisory. No fuzzy matching; distinct incident IDs may share a tuple. Agents decide whether to observe after inspecting facts.
* `incident suppress I-n --task T-n --assignment <key> --observation <id> --reason <text>` only confirmed/mitigated incidents; task must be nonterminal and observation active, from that task/incident/current condition version, with exact tuple equality. Require explicit evidence and reason. #orchestrator suppresses only orchestration; validator key suppresses only that role. Same existing active suppression is idempotent; no duplicate events. No task lifecycle/owner/lease mutation.
* `incident recover I-n --kind <probe|configuration> --evidence <text> [--configuration <new value>]` records successful bounded probe evidence or measured configuration/capability change. Require confirmed/mitigated state. Probe means the caller attests successful bounded probe for this exact condition; CLI help must state this. Configuration requires a nonblank different configuration value; probe disallows configuration flag. Both increment ConditionVersion, release existing active suppressions for this incident, and record previous version and new version. Probe transitions to mitigated (does not assert resolved); configuration leaves incident state unchanged. Existing observations remain historical and must be freshly observed before suppression can be rearmed. Does not change dependencies, state, budgets, attended flags, holds, requests or validation subjects. Never executes evidence as a command. Every recovery emits an attributable incident event and release events naming affected pairs.
* `incident metrics I-n [--hours N]` read-only, N defaults 24, 1..720. Window and linked-task cohort explicit. Include observation count, distinct task count, explicit diagnosis update count (label as recorded diagnosis updates, not actual sessions), unlink corrections, suppression/release counts, and per-task recovery-to-first-subsequent conductor staffing elapsed seconds when observed. Separate conductor staffing attempts from actual process starts, worker runs and successful task outcomes; report unavailable process/session attribution as null plus missing-data explanations, not zero. Include source event sequence IDs and implementation revision if available, otherwise unknown. Do not assert speedup or infer that every unlink was a false suppression. A released suppression due to unlink is an explicit grouping correction, report separately.

HTTP: GET base/list, GET /{id}, GET /matches, GET /{id}/metrics; POST base/add, POST /{id}/update, /transition, /observe, /unlink, /suppress, /recover. API and CLI behavior identical. Project defaults follow existing CLI project-context behavior. Requests validate whitespace, bounds (title 300, tuple parts 1000 each, evidence/diagnosis/workaround/recovery/reason 16000, authorization/run 2000), malformed IDs, absent project/task/role/incident, cross-project links, mismatched observation, illegal state. Missing resource -> existing not-found conventions; invalid input -> 422 stable codes incident_input, incident_transition, incident_scope, incident_evidence; mutation against terminal task -> incident_task_state. Claim conflict -> 409 incident_wait. Never crash on malformed input. Expose raw retained evidence only as JSON strings, with normal encoding.

### Suppression integration

Implement one shared query/helper for effective suppression: active suppression + active evidence observation + equal current ConditionVersion + incident confirmed/mitigated + task nonterminal. Use it in ConductorService PlanOrchestratorsAsync and PlanAsync, before staffing and without counting a suppressed pair as an attempted session. Existing gates still apply independently. Also refuse a new task claim when #orchestrator suppression is effective (same-owner renewal remains allowed); reject only that task, with incident ID/reason/recovery guidance. Do not suppress unrelated validators, tasks, projects, landing or in-flight sessions. No periodic timeout auto-retry of unchanged conditions. Restart uses persisted rows, not in-memory state. No event emitted per scheduler read/tick.

Append optional IncidentSuppressions field to ConductorStatusDto, listing each effective task/assignment/incident/version/reason/recovery condition (even if another gate also blocks it). Append optional Incidents field to TaskDetailDto, containing linked incident context and effective suppression details so task show explains every incident gate and preserves task events. Existing clients/tests constructing positional records remain compatible through optional defaults. Add incident events with incidentId in every payload; task-specific observe/unlink/suppress/release records also carry TaskId. Event types: incident.created/updated/transitioned/observed/unlinked/suppressed/released/recovered. Show events by payload incident ID without assuming TaskId exists.

Intake/failed-run triage: document `incident match` then show/observe workflow in kit/core/orchestrate.md and kit/core/oncall.md if present, without altering protected .claude files. Matching is explicit read-only intake/triage action, no automatic text extraction. Read-only pilot proposal demonstrates this workflow against historical signatures.
