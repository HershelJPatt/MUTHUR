## Design
1. Add vendor-neutral serializable launch-side records in Muthur.Launch: CapabilityIdentity (Machine, Harness, HarnessVersion, LaunchPath, ConfigurationHash, RepositoryRoot, BaseCommit); CapabilityObservation (identity, capability key, state, observedAt, expiresAt, evidence, durationMilliseconds); CapabilityMatch (allowed, missing with states/reasons, authorized alternative if actually evidenced). State values: available, unavailable, unknown, stale, temporarily-failing. Use injectable TimeProvider. Identity equality is ordinal with canonical full repository path; configuration is SHA256 over canonical effective allowed/denied commands, model/reasoning, Git environment, executable path, relevant harness settings content hashes and execution path. Never persist secret values. Paths worker-run, conductor-validator, conductor-orchestrator, native-subagent must never cross-satisfy. Harness/version/config/base change invalidates records; missing/unreadable identity input means unknown, never reuse prior success. TTL max 24 hours, transient failure 5 minutes. Unknown/stale/temporary/unavailable all refuse explicit required capabilities.
2. Requirements use a standalone `capabilities: shell, build, test, worktree-base, commit` line in frozen markdown. Accepted keys also include headless-interaction, connector-interaction, platform:<name>, native-agent-tools. Multiple lines union; malformed/unknown bare keys refuse with actionable error. Existing specs without capabilities retain current routing (incremental rollout). Existing needs: browser handling remains unchanged. Native-agent-tools can only be satisfied on native-subagent launch path; documentation names T-67/T-97. Headless and connector keys are independent. Platform keys require explicit evidence. No automatic inference from executable discovery or other route success.
3. Provide CapabilityStore under chosen MUTHUR_HOME/capabilities using atomic per-identity JSON replacement and bounded reads; malformed/missing records return unknown with diagnostics, not crashes. No global/static cross-home cache. Reads never mutate. Cache writes contain only observation data; bounded detail lengths and no stdout dumps. Process/version discovery uses existing IProcessRunner, short timeouts and cancellation. Hash relevant known harness settings through harness adapter-owned implementation in Launch; never vendor strings in hub/Core/Contracts. Unknown adapters fail closed when requirements exist.
4. Add optional capability context to WorkerRequest (requirements, launch path, cache directory, base commit). Integrate matching before full process start in WorkerLauncher and AgentLauncher. Pass-over attempts have Started=false, FailureKind=capability_mismatch and detailed missing states; no identity allocation for rejected agent routes. Empty requirements preserves old behavior. WorkerCommands parses spec from pinned assignment; validator launcher reads the task's committed spec/branch using existing repo seams; orchestrator may use stored frozen spec when available, otherwise no new requirements. Never read an unrelated dirty spec. Propagate diagnostic through existing conductor refusal/stall handling. A supported alternative is only named if another existing catalog candidate independently matches exact requirements; never suggest widening permissions.
5. CLI `muthur capability inspect --spec <path> --base <ref> --default-branch <name> --harness <name> --launch-path <path>` displays current identity, requirements, states and match; does not launch model sessions or mutate. `muthur capability probe` takes same inputs plus --timeout-seconds (default 90, max 120). It runs at most one bounded probe via existing authorized harness adapter launch path (worker-run only in first slice); other paths return unsupported/unknown with no launch. The bounded probe engine is implemented behind an explicit admission interface in Launch and tested with an admitted fake runner. Production CLI admission is fail-closed in this slice: return capability_probe_admission_unavailable without invoking a model because main has no shared worker budget/capacity reservation seam. Inspect remains functional. It must not automatically run in doctor/conductor or retry. Do not circumvent catalog, account, budget or process ceiling enforcement; if existing worker route cannot honor a gate, return unavailable and report the missing integration rather than bypass it.
6. Probe body is fixed and bounded: in a disposable worktree pinned to requested base, ask harness to execute a generated deterministic probe script through its shell tool. Script performs shell nonce check, git rev-parse HEAD, and an isolated offline tiny .NET project build and test command; no package downloads, external services or product code execution. It writes per-step exit/status evidence with a fresh nonce into scratch. Use dotnet SDK's built-in MSBuild project with explicit Build and Test targets to avoid external test packages. Script failure of one step does not manufacture successes for another. For commit capability, commit only a generated file in disposable probe repository and verify HEAD changed there; never commit on task/default branch. Only verify step receipts plus resulting outputs/HEAD; model prose and exit 0 alone are insufficient. Evidence must identify the exact tested fixture/commands and limitation: proves tool execution and SDK route, not arbitrary project's correctness. No receipts => unknown; deterministic command denied/not present => unavailable; timeout/process/transport failure => temporarily-failing. Do not mark browser/platform/native-agent capabilities available. Always cleanup probe descendants and disposable worktree in finally; preserve concise evidence outside it. Probe scratch execution uses exactly intended worker permissions/config and records probe overhead separately from full starts. No automatic allowlist additions to make the probe succeed.
7. Doctor adds read-only capability check reporting cached observation counts, stale counts and unknown coverage with useful `capability inspect/probe` guidance; --probe does not invoke models. Expose matching evidence via worker JSON and conductor diagnostics. Extend existing worker-attempt output compatibly to include match details and distinguish probe starts, rejected mismatches, full starts, and full sessions avoided (only count a rejected full launch, never success). No additive overlapping success claims. Cache entries store times/revision and tests assert telemetry semantics.
8. Document spec syntax, cache invalidation, probe limitations, recovery (remove only selected stale cache then explicit authorized re-probe), incremental opt-in, and T-94 seam in kit/core/spec-template.md, kit/core/orchestrate.md and docs/capabilities.md. Do not edit installed .claude rails. Browser integration and unavailable native route remain named follow-ups to existing T-94/T-67/T-97, not falsely completed pilots.
