## Context

ProbeAdmissionTests.Admission_and_each_launch_class_share_the_gate assumes invocation order establishes gate order. RunPassAsync awaits EnabledAsync before taking _pass; AdmitProbeAsync takes _pass before its ledger mutation. A held ledger writer therefore does not establish the pass as winner. This is a test contract defect; production permits either winner in an unordered race.

## Non-goals
No production edits, priority changes, sleeps, retries that hide failures, new packages, capacity changes, or new public testing hooks. Do not alter unrelated admission tests or fixture policy. No live hub use, outbound calls, push or merge.

## Design
Keep coverage for validator, orchestrator, overseer. Factor the existing setup within ProbeAdmissionTests only as needed to reuse it.
1. Deterministic ordered theory: six cases (three classes times admission-first/pass-first). Await the first route to completion before invoking the competing route; blocked fake sessions keep a conductor winner live. Admission first must grant MayExecute, then both competing passes return zero and no launcher starts. Pass first must start exactly one, then admission throws MuthurException with probe_capacity_exhausted. Assert the selected fake launcher started once, other launchers not at all. Await HeldProcess.Started for overseer with a hang-detector timeout.
2. Retain actual contention in a separate six-case theory using the existing held ledger writer and both invocation orders. Both calls must be issued while the writer is held. Do not predict the winner from call order. Observe both results (including admission exception): the only valid outcomes are MayExecute=true with pass=0, or pass=1 with exactly probe_capacity_exhausted. No other exception is accepted. Assert zero or exactly one appropriate fake launch and admitted event count in accordance with the actual winner. A second pass must start zero.
3. In both theories, after completed routes assert StatusAsync.Running == 1 and Sessions.Count == 1. Winner remains held until these checks, so any double grant cannot disappear before observation. Assert number of granted probe events plus actual launcher starts equals one. Ordered theory checks status after first route as well.
4. Put all asynchronous operations and assertions under try/finally. Track writer, pass and admission tasks before assertions; finally always release the writer, cancel a per-test cancellation source, observe/join every started operation, release any successful probe reservation (even if a prior assertion failed), and call StopSessionsAsync. Cleanup must not abandon other tasks if one faults. Use Task.WhenAll/Record.ExceptionAsync or explicit per-task observation; expected cancellation/refusal can be observed without being rethrown from cleanup. Main assertions must still surface unexpected failures. Bounded WaitAsync may detect hangs, never provide ordering. No Task.Delay/Thread.Sleep. Explain invocation vs acquisition order in a short comment.
5. If current-main fixtures no longer create an eligible validator, report the concrete issue before broadening scope; do not weaken the one-launch assertion.
