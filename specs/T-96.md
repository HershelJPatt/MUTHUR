## Design
Create tools/Muthur.XmlDocCheck/Muthur.XmlDocCheck.csproj (net10.0 console) with SDK-shipped Microsoft.CodeAnalysis and Microsoft.CodeAnalysis.CSharp references via $(MSBuildSDKsPath)/../Roslyn/bincore, copied locally. No new NuGet dependencies. Public reusable checker API lives here; tests reference it. Add tests/Muthur.XmlDocCheck.Tests with the same xunit/test SDK conventions as Core.Tests. Add both projects to Muthur.slnx.

Console accepts zero arguments (current working directory repository) or --root <directory>. Resolve git root using git -C root rev-parse --show-toplevel; enumerate git -C root ls-files -z -- src tests; read current working tree content for each tracked file, not index contents. Handle spaces and Unicode correctly. Missing/unreadable tracked files and git/argument failures are infrastructure errors with nonzero exit, never silently green. Use process argument arrays. Git safety exceptions may be command-local for the explicitly selected root only. Sort normalized slash-relative paths ordinally.

Only .cs files under exact src/ or tests/ qualify. Exclude path segments bin and obj; conventional filename suffixes .g.cs, .g.i.cs, .generated.cs, .designer.cs (ordinal ignore case); files with <auto-generated or <autogenerated markers in leading C# comment trivia (case insensitive; never matching ordinary string literals); and the explicit intentional probe directory tests/Muthur.XmlDocCheck.Tests/Fixtures/. Document these exclusions, including EF generated files carrying markers. Do not broadly exclude arbitrary directories called Fixtures. Fixtures should normally be inline strings or noncompiled .txt assets.

Parse with Roslyn CSharpSyntaxTree and DocumentationMode.Diagnose, latest language version. Declaration ownership: MemberDeclarationSyntax and LocalFunctionStatementSyntax, including enum members, fields/events as one declaration; exclude namespace declarations as non-documentable containers. Inspect documentation trivia in the leading trivia of the declaration's first token, including before attributes. Collect ALL attached single-line or multiline documentation trivia there, even separated by whitespace or ordinary comments. Each syntactic partial declaration is independent. Never combine different declarations, parameters or compilation units. Stranded comments have no owner and are ignored.

For each owner's complete documentation group: if any documentation trivia has XML parse diagnostics, skip that group (malformed XML belongs to separate compiler assessment). Otherwise count ONLY direct XmlElementSyntax or XmlEmptyElementSyntax named exactly unprefixed summary in each DocumentationCommentTriviaSyntax.Content. Nested tags, examples with CDATA/escaped text, prefixed names, and textual strings do not count. When count exceeds one emit one MUTHURXML001 at the opening '<' of the second summary, with 1-based line/column and message 'Declaration has multiple direct XML summary elements.' Third/further summaries do not add diagnostics for that declaration.

Conditional compilation: discover identifiers used in #if/#elif expression syntax; enumerate all boolean assignments for each file (including default empty set), parse each, and union diagnostics by relative path/line/column/code. This checks inactive branches without trying to infer project symbols. Limit to 12 unique conditional symbols per file; above that fail explicitly as infrastructure/unsupported scope, never skip silently. Test both branches and duplicate diagnostic deduplication. A #define/#undef retains normal C# behavior. This is syntactic possible-configuration coverage, not semantic project configuration validation.

Expose pure source/path analysis separately from Git enumeration for tests. Console writes deterministic 'path(line,column): error MUTHURXML001: Declaration has multiple direct XML summary elements.' lines. Exit 0 clean, 1 duplicates, 2 arguments/infrastructure (brief stderr). Normal test integration: one repository baseline test locates root by walking from AppContext.BaseDirectory to Muthur.slnx and .git (file or directory), calls the same tracked repository scan, and asserts zero diagnostics. Missing root/git fails. Therefore ordinary dotnet test enforces the policy without coupling runtime assemblies or MSBuild compilation to the checker. Standalone console is available for focused checking.
