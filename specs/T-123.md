# T-123 — Make XML repository fixture cleanup deterministic on Windows

> Frozen spec. Stop and report if this spec is wrong or incomplete; do not improvise.

## Goal
Make XML test repository cleanup tolerate a transient Windows sharing violation within a strict bound and fail visibly when cleanup cannot complete. Preserve all policy assertions and verification gates.

## Design
Create internal test-only RepositoryFixtureCleanup in tests/Muthur.XmlDocCheck.Tests/RepositoryFixtureCleanup.cs. Its Delete(string root) operates only on the supplied fixture root and asserts/verifies root absence on success. Normalize readonly files as the existing fixture does, using enumeration that skips reparse points and does not ignore inaccessible files. Do not traverse reparse-point directories. Each attempt repeats normalization and recursive deletion, allowing a partially deleted tree. Missing root is success.

Retry ONLY IOException whose full HResult equals HRESULT_FROM_WIN32(ERROR_SHARING_VIOLATION=32) or ERROR_LOCK_VIOLATION=33, and only on Windows. All other failures propagate immediately. Use Stopwatch elapsed time with a five-second hang-detector budget and SpinWait.SpinUntil observing the delete-success condition; no arbitrary sleep to synchronize tests. Check deadline before additional attempts. On exhaustion throw IOException with absolute root, attempt count, elapsed time, HResult and the last original exception as InnerException. Never return success while Path.Exists(root). No retries of test bodies or Git calls.

Provide an internal core overload/seam taking a delete-attempt Action, Windows-platform flag and a retry-driver delegate (Func<Func<bool>,bool>), so tests can drive retry attempts synchronously without real delay. Production binds the retry-driver to the bounded SpinWait. The predicate returns true only on deletion success, false only on the allowed transient exception; other errors throw. A false retry-driver result throws the terminal cleanup exception described above. First attempt must occur even for a zero/exhausted test budget. Keep this seam internal to the test assembly.

Use the helper for both WithRepository and Nonrepository_and_missing_directory_fail. Retain unicode/space paths, readonly normalization and all existing assertions. Preserve both body and cleanup failures: run body capturing ExceptionDispatchInfo, attempt cleanup, rethrow original with its stack if cleanup succeeds; AggregateException containing both original exceptions if both fail. This orchestration may be extracted into an internal test helper Run(string root, Action body) in the same class for direct regression coverage. It must clean up if setup/body throws.

Add deterministic tests: missing and ordinary/read-only directories removed; simulated Windows 32 and 33 fail once then succeed with exact attempt count; permanent sharing violation exhausts an injected finite retry driver and remains fatal with original exception/root details; unrelated IO and unauthorized errors fail immediately; same HRESULT on non-Windows fails immediately; body failure still cleans and preserves original; simultaneous body/cleanup failures preserve both. On Windows, hold an actual FileStream(FileShare.None) in an owned temp root, observe actual deletion failure, release that handle synchronously in the injected driver after the first failed attempt and verify deletion succeeds. Also keep a real handle held across a finite driver, assert terminal failure and remaining root, then dispose and delete in finally. Tests must leave no owned handle/root, including on assertions. No timing sleeps, subprocesses or guessed lock-holder claims.
