# T-83 — Refuse hard-linked kit write destinations

> Frozen spec, implementing approved technical request 40 (event 4395). Stop and report a spec problem rather than inventing policy.

## Goal

Before kit install mutates any destination or creates directories, refuse an existing file it would change unless its native hard-link count is exactly one. Preserve create/unchanged behavior and transaction rollback. A hard link outside (or inside) the repository must never receive installer bytes.

## Context

Base: main 6cf2fb3. KitCommands.TryReadManifest/Unwritable/Writes already preflight destinations, including .gitignore and muthur.project.json. InstallTransaction.Rendered defines write intent; Write and Rollback mutate file contents in place. T-57 resolves symlinks/junctions but cannot detect hard links. Read CLAUDE.md and these files in your own worktree. Request 40 explicitly approved write-only refusal and fail-closed inspection.

## Non-goals

No alias enumeration, atomic-replacement redesign, source hard-link restriction, schema/API/CLI additions, or changed write modes. No protection from concurrent filesystem mutations between preflight and writes. No new platform runtime dependencies or shell commands in production inspection.

## Design

1. Keep existing containment, collision, directory/ancestor and read-only checks and diagnostic precedence. Add a full hard-link preflight after existing Unwritable checks and before returning validated entries. It includes manifest destinations and installer-owned destinations. Use the actual path through any inward links; native inspection follows the final file target.
2. Only inspect existing destinations that Writes says would change. Preserve kept create entries, normalized-equal replacement entries, unchanged section entries, existing project files (unless a manifest explicitly changes them), and .gitignore already containing the worktrees rule. Missing destinations need no count. A manifest's duplicate entries remain last-one-wins; any entry that would change an existing multiply-linked file causes refusal even if a later entry restores it. This conservative per-entry check is sufficient for the existing write modes.
3. Do not interpret File.Exists=false as proof of absence for the new check. Classify via File.GetAttributes; only FileNotFoundException/DirectoryNotFoundException means absent. Other access/IO errors refuse. Catch IO/access errors while computing write intent too, with destination/reason, rather than relying on the manifest reader's last-resort defect guard.
4. Internal helper src/Muthur.Cli/Infrastructure/HardLinkInspector.cs exposes a result containing success, unsigned count, and failure reason, plus a testable platform-selection seam. No static mutable global test hook or user-configurable bypass. Pass an optional internal inspector delegate through a test overload of TryReadManifest to exercise failure results; normal command always uses the native inspector. Count zero is inspection failure. Handles are disposed. Return actual OS error code and API name for native failures; missing entry points/libraries, unsupported platform/architecture and missing statx result mask are explicit failures, never count one.
5. Supported native combinations (all other combinations fail closed only when inspection required):
   - Windows x64 and Arm64, Win32 GetFileInformationByHandle with BY_HANDLE_FILE_INFORMATION (52 bytes, NumberOfLinks uint at offset 40). Open read handle with File.OpenHandle and FileShare.ReadWrite | FileShare.Delete. Use blittable struct and AOT-safe P/Invoke. No write access required.
   - Linux x64 and Arm64, little endian, libc statx export implementing Linux statx UAPI (glibc or musl). Call statx(AT_FDCWD=-100, UTF-8 absolute path, flags=0, STATX_NLINK=4, buffer). Fixed UAPI buffer 256 bytes, mask uint offset 0, nlink uint offset 16. Require returned mask bit 4. No fallback to platform-dependent struct stat or guessed syscall number; unavailable libc symbol/kernel/filesystem capability refuses explicitly.
   - macOS x64, Darwin 64-bit inode ABI: libSystem.B.dylib stat$INODE64, UTF-8 path, 144-byte struct stat; nlink ushort at offset 6. macOS Arm64: libSystem.B.dylib stat with the same Darwin LP64 64-bit-inode layout. Gate architectures explicitly, do not apply this layout to any other Unix. Follow symlinks with stat, not lstat.
   - Source layout references: https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information ; https://raw.githubusercontent.com/torvalds/linux/master/include/uapi/linux/stat.h ; https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/sys/stat.h . Include short source references by native declarations; copy no license boilerplate or large excerpts.
6. Refuse via existing invalid_manifest / exit 2 before all writes. For a manifest entry use prefix `{manifestPath}: entry {index} writes "{spelled}"`; for own files use `kit install writes "{spelled}"`. Count >1 suffix: `, which has {count} hard links; replace it with an independent file before installing.` Inspection failure suffix: `, but its hard-link count could not be determined: {reason}. No files were written.` No address dump or misleading generic reader-defect text.
7. Leave InstallTransaction forward and rollback mechanics unchanged: preflight excludes all initially multiply-linked files that could be journaled/written. Preserve existing T-57 and T-55 tests.
