## Design
Add benchmark code under tests/Muthur.Server.Tests/Benchmark/ and an xUnit entry test tagged Category=WorkflowBenchmark. Use existing HubFactory and real TestRepo, fake launchers and fake clock; every trial gets a fresh hub/repo and disposable HTTP clients. Retain sanitized HTTP responses, task/event snapshots, git heads and graded file contents before disposal. Never retain bearer tokens. Scenario definitions live in benchmarks/workflow/scenarios.v1.json, version 1, with stable id, historical/forward cohort, source incident, initial state, scripted events, expected outcomes, failure conditions and resources (zero paid sessions, zero model calls, max scripted starts, fake elapsed bound). Copy manifest to test output. Add focused grader/report tests in the same directory.

Implement these historical scenarios, independently selectable by id:
1. stale-spec (T-50): reject absent/wrong-task spec then attach a committed valid task-branch spec, implement and independently validate/land good result.
2. interrupted-owner (T-95/task lease): expire owner with fake time and lifecycle sweep, replacement claims and completes same task; no duplicate completed task.
3. late-verdict (validation claims): expire first validator claim, second claims; stale first verdict refused, current holder completes and good branch lands.
4. dependency-wait (T-95): dependent cannot proceed while prerequisite incomplete; complete prerequisite, resume dependent and land; blocked fake duration separately recorded.
5. conflicting-branches (land conflict): conflict leaves main unchanged and task not done; scripted correction/rebase and a fresh required validation allow good landing. Verify repository file, not just status.
6. false-green (historical wrong implementation): scripted worker reports success and validators approve an intentionally wrong result.txt value; land in scratch and external grader rejects product correctness despite done status. Expected detection makes this negative-control scenario pass; retain productCorrect=false, falseApproval=true, detected=true separately, never count it as successful product completion.
7. no-verdict-loop: use real conductor with fake session launcher and fake clock to reproduce existing bounded retry/cooldown contract; verify observed attempts/start calls, stop at cap, one escalation; do not manufacture ledger observations.
A good completed result is main:result.txt exactly `42` after trimming one terminal newline. Keep grading separate from worker report and task status. External grader requires expected terminal state and git result for positive completion; missing/invalid evidence fails closed. Add tests mutating evidence / success claims, missing files and wrong contents to show false green cannot pass.

Reports: per-trial JSON plus raw evidence, aggregate JSON and readable Markdown. Include schema/scenario suite version and content hash, run id, resolved product revision, benchmark driver revision, cohort, scenario id, trial index, UTC window, sample count, process wall-clock stopwatch duration, fake-clock phase intervals and blocked time distinctly. Counts separately name staffing attempts, actual OS starts, scripted launcher invocations, worker runs, human interventions and successful outcomes; unsupported values null with reason (never infer actual starts from registration). Tokens/cost null/unavailable; paid/model calls 0 by construction. Agent behavior unmeasured; product/orchestration results separate. Aggregates include counts and min/max/mean wall duration, no speedup claim. Never sum task-hours as wall-clock time. A detected negative control contributes detection coverage, not product success.

Add scripts/benchmark-workflow.ps1 with parameters -Baseline <git revision> -Candidate <git revision> -Output <new directory> [-Scenario <id>] [-Trials <positive integer, default 1, max 10>] [-Mode deterministic|real, default deterministic]. Resolve and validate revisions first. real mode writes a visibly unmeasured report (reason: no approved admitted real-harness route in this slice, budget zero), performs no harness calls and exits nonzero. deterministic mode creates uniquely owned scratch checkouts via git archive (not live working tree), overlays only this benchmark's test files + manifest and required project content entry onto each revision so the exact same grader drives both revisions. Compile/test each scratch revision; incompatible revision is unmeasured/error, not green. Do not copy product source from driver revision over target source. A runner environment variable configures artifact root, pinned identities, trials/selection. Entry test normally runs small suite in full dotnet test; in runner write full reports. Run dotnet test filtered Category=WorkflowBenchmark with TRX plus captured log. Nonzero test/build, missing trial, unknown scenario, missing evidence, mismatch suite/cohort or interrupted run gives nonzero command exit and explicit incomplete/error report. Compare only identical scenario version/hash/cohort/trial configuration; retain per-revision data and aggregate comparison. Preserve raw logs and evidence outside scratch cleanup. Use bounded child-process execution with finally cleanup; terminate only children created by this invocation. Delete only verified paths under the unique owned scratch root, reject existing output directory to avoid deleting/overwriting user data. Isolate MUTHUR_HOME/MUTHUR_URL and credentials/agent identity in child environment; never execute muthur CLI in this script. No network or live ports necessary for in-process hubs. Provide deterministic cancellation/failure cleanup tests and a bounded fault injection switch for runner interruption testing if needed; no sleeps for test synchronization.

Document docs/workflow-benchmark.md: command, schema/count semantics, scenario map, targeted runs, missing data, separate historical/forward cohorts (forward initially empty), how to add cases, offline recovery/cleanup, real trials unmeasured, baseline pinned to 89dc34c. Record first real deterministic use against baseline and candidate with actual counts/revisions in verification evidence; do not prepopulate claimed results.
