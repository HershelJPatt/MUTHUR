# T-104 — Approved objectives and observable outcomes

> Frozen spec. Implement only the assigned unit. Stop with evidence for a missing design decision.

## Goal

Add a small, vendor-neutral objective ledger and read-only Outcomes view. An objective names existing approved work, baseline, measurable success condition and observation window. Delivered tasks are evidence of capability, never automatic evidence of an achieved outcome. No prioritization, staffing, model calls, outbound activity or permission changes result from an objective.

## Design

### Durable representation

Use keys `objective.<id>` in Meta, JSON with web defaults, formatVersion=1; IDs `O-1`, `O-2`, etc allocated within Ledger.MutateAsync using `objective.next-id`. All writes record objective events with objective id and revision in payload, with TaskId null (an objective is not a task). Register all HTTP/CLI DTOs in MuthurJsonContext. Do not reuse task priority or alter WorkTask.

An ObjectiveDto contains Id, Project, Owner (identity name), Title, current Revision (integer), State (`observing`, `achieved`, `superseded`, `abandoned`), CreatedAt/UpdatedAt, immutable revision list, task-link list, evidence list, effort list and immutable acceptance history list. Each acceptance includes revision, observation key, actor/time and reason; the current acceptance is derived from state/current revision while old acceptances remain visible after amendment or closure. A revision contains number, actor/time, approval source, Outcome, Scope, Baseline, SuccessCondition, WindowStart/WindowEnd, Metric, Target (decimal), Comparison (`at_most` or `at_least`), MinimumSample (positive integer), reason, previousRevision. SuccessCondition must describe the condition in plain language; the numeric fields make its measurable part enforceable. Baseline is a MeasurementDto: Value nullable decimal, Quality (`measured`, `estimated`, `unknown`), Unit, SampleCount nonnegative, From/To, Cohort (task IDs), Revisions (strings), Evidence (nonempty reference), MissingData (string). Unknown requires null value; known requires value; empty samples may have counts but must not imply demonstrated outcomes. Baseline and observation windows must be valid ordered UTC timestamps. Observation must be after baseline ends (equality allowed).

Approval source: task id plus exact founder-origin `task.added` event seq OR answered human request id plus its founder-origin `request.answered` seq. Validate existence, same project/task association, actor `founder` with null ActorAgentId, correct type and matching id. Return approval source's full source task body or question/answer and actor/time in the view. A citation records pre-existing authority; it grants no task execution, spending, permission or outbound power. Do not infer approval from an agent note or technical answer. The caller is accountable for accurately describing the already-approved outcome; label this `Recorded approval reference` in the UI, not machine-verified semantic approval. T-104's founder-added event 5312 plus its body is the dogfood authorization to record the approved improvement program and choose an internal measurement.

Ordinary registered agents, subject to all pre-existing caller restrictions, may create records citing that prior authority; owner is always caller.Name (founder may choose owner). They cannot subsequently change approved outcome/scope/success/owner. Amendments, supersede/abandon and acceptance require the actual founder caller, not a cited event or an owner. This deliberately makes later conflicting human direction authoritative. A founder amendment appends a complete revision with reason and approval reference, resets state to observing, preserves all old evidence and effort, and invalidates previous acceptance for the current revision. New revisions never silently overwrite old ones. Require expectedRevision on all writes to existing objectives, conflict 409 `objective_revision` on stale values. Supersede points to an existing objective in same project, cannot point to itself; abandonment requires reason. Superseded and abandoned records refuse evidence/link/effort writes until a founder amendment reopens them. Achieved is distinct from those closed states: owner/founder may append regression and note evidence, and founder may append explicit effort, while achieved; observation/capability evidence and task-link writes require observing. Post-acceptance regressions leave achieved state and its original acceptance untouched and are visibly flagged for review. A founder amendment is the only reopening mechanism and retains prior acceptance history. No deletes.

Task links: canonical task id, role (`enabling`, `capability`, `follow_up`), note. Owner/founder may add a link; same task is one link (upsert role/note with audit), same project only. Linking does not mutate task. Cap 200 unique tasks. UI distinguishes linked capability with Done state (`delivered capability`) from accepted outcome; enabling/follow-up Done is not relabeled outcome. Resolve dependencies live, include unfinished dependencies even when not directly linked; cancelled is unresolved. Expose pending task requests with original question/answer/Kind/RouteReason. Links to existing tasks and /needs-you; do not ask or answer requests implicitly. Historical unlinked tasks remain usable.

Evidence append: unique client key (1..120 chars; replay same content returns existing, different content conflict `objective_evidence_key`), revision, kind (`observation`, `capability`, `regression`, `note`), measurement, description, task optional, ledger event seq optional, actor/time. Owner/founder only. Supplied task/event must exist and be attributable to a linked task; preserve external evidence references as text, never fetch them. Observation measurement Metric/Unit and cohort must match revision (cohort equals baseline cohort as a set), from/to must equal objective observation window, revisions nonempty. Other evidence may have missing values. MeasurementDto includes Metric in addition to the fields listed above. The future measurement SampleCount for the dogfood metric counts task.claimed events; it does not count duplicate parkings. Every evidence row is attributed and immutable.

Acceptance: founder-only POST accept with expectedRevision, observation evidence key and reason. Require observing state, current-revision observation, full window ended by injected clock, measurement Quality=measured, nonnull value, sample >= MinimumSample, no MissingData, correct unit/cohort/metric/window, numeric condition true. Reject with 422 `objective_success_not_demonstrated` otherwise. Task completion alone never accepts. Founder explicitly judges the textual success condition/validation guardrail in reason; UI calls acceptance `Founder accepted outcome` with evidence key, actor/time/revision/reason. It is not an automated scientific causality claim. Additional regressions remain visible and do not silently rewrite history. Repeated accept refuses conflict rather than adding accepted outcomes.

Effort append: unique key with idempotence like evidence, Minutes >0, quality measured/estimated only, period From/To, actor/time, source reference, note. Founder-only: agents must not invent founder minutes. Each objective effort key is one allocation, not whole-program time to repeat per task. View shows entries and measured/estimated subtotals separately; unknown if no entries. `accepted outcomes per founder hour` is null unless current objective is accepted and positive explicit effort exists; report measured and estimated denominators separately (never mix them into a false measured rate), ratio 1/(minutes/60). Never infer effort from blocked/elapsed/task times.

### Read view and resource attribution

GET list returns summaries ordered by numeric objective id, optionally project filter. GET detail returns durable record plus projection: linked task titles/states/roles, delivered capabilities, unresolved dependency edges and reasons, open decisions with routing, observation status (`not_started`, `pending`, `window_ended`, `accepted`) from clock/current state, current acceptance, revision/evidence history, resource report. No percentages.

Resource report window is current observation window clipped at now (empty before start); label bounds, linked cohort IDs, current host revision if known, samples and missing dimensions. Query original ledger rows for distinct linked task IDs; every event is counted once despite role changes or shared dependencies. Dependencies outside cohort are shown as blockers but not silently charged. Worker run rows retain Seq/RunId, task, worker/account, seconds, cost, tokens, status and revisions as receipts do. Deduplicate matching nonempty RunId (latest Seq); legacy missing RunId rows remain separate with explicit missing-identity warning, not fabricated equivalence. Costs remain per-row (no total with incomplete reporting); duration labeled recorded worker run-seconds, not wall time. Separate conductor staffing attempts, actual starts where an explicit start event exists, worker terminal reports and task waiting intervals; never add these counters. No source for starts => unknown, not staffing count. Task waiting from TaskStateTimeline, clipped window; overlapping task durations are task-seconds, not human time.

Track delivery samples: for linked tasks landed within window, createdAt-to-first-landed seconds, n, median and nearest-rank p90 (ceil(.9*n)-1), task/revision refs; small sample note when n<10. Existing records without creation/landing evidence => missing, never zero. Track repeated dependency parking as a narrow proxy: consecutive task.dependencies_set events with any same dependency, with no intervening task.dependencies_ready for that task; count duplicate parking events, one per event regardless of shared dependencies, label proxy (not all repeated diagnosis). Show founder-authored request.answered count as interventions, not hours. Post-validation regressions are explicit kind=regression evidence only; absent coverage => unknown, not zero. Show accepted outcomes as 0/1 for this current objective revision, not count of done tasks. Reuse helpers where safe; do not modify unrelated receipt aggregation.

### API / CLI / dashboard

Routes: `/api/v1/objectives`, `/api/v1/objectives/{id}`, and POST suffixes `amend`, `link`, `evidence`, `effort`, `accept`, `close`. GET unauthenticated like receipts; POST requires identified identity plus above rules and every pre-existing caller restriction. In particular organization-overseer remains unable to POST objective mutations under Auth/Caller.cs; do not modify its middleware allowlist or any auth file. Registered does not imply an exemption from that restriction. Add a regression test for this refusal. Creation POST accepts title, project, optional owner, revision definition. Amend takes expectedRevision, definition, reason. Link/evidence/effort/accept/close use requests described above. Close state only superseded/abandoned, reason, optional supersededBy. Validate all strings required/nonblank; title <=200, outcome/scope/success/notes/references <=8000; cap 100 revisions, 1000 evidence and 1000 effort rows; validation failure 422 `objective_input`, unknown record 404, invalid transitions 409 `objective_state`, wrong identity 401/403 using existing Fail.Unauthorized convention. Malformed JSON returns a controlled CLI error, not a stack trace. Never silently truncate source evidence.

CLI commands `objective create --file <json>`, `objective list [--project]`, `objective show O-n`, and `objective amend|link|evidence|effort|accept|close O-n --file <json>`. DTO-typed deserialization with generated context; JSON responses via Output.Emit, shared Routes methods, no model or process calls. Document concrete JSON examples for every mutation. No --approved flag that bypasses checks.

Dashboard `/outcomes` index and `/outcomes/{id}` detail, read-only, normal prerendered HTML (no Virtualize), LivePanel refresh for objective/task/request/worker events. Add Outcomes nav beside Receipts. Render all fields above with honest measured/estimated/unknown labels, history, sample counts, dates, IDs and references. Link to tasks using existing route convention, no external auto-fetch. Use app.css classes, no inline styling, and accessible semantic headings/tables. Missing O-n renders clear not-found content, not 500. Source body/history may use details elements, safely encoded.
