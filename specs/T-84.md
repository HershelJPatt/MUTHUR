# T-84 — Resolve working-tree spec containment through links

> Frozen spec. Implementer stops and reports missing design decisions.

## Goal
TaskService must refuse working-tree specs whose filesystem paths escape the project checkout through junctions or symlinks, preserving legitimate inward links, linked project roots and Git-branch specs.

## Context
Read CLAUDE.md, specs/T-57-junction-containment.md (especially measured platform table), TaskService.RequireSpecBelongsToTaskAsync, Muthur.Launch/RepoFile.cs and SpecGuardTests.cs. Base: task/T-84-spec-containment, created from main 20b709d. Verify base ancestry with git log. T-57's helper walks each component. The server explicitly walks immediate link targets from their volume root and tests target-ancestor junctions, rather than assuming every target spelling is already canonical. A local Windows probe resolved the target-ancestor fixture with File.ResolveLinkTarget(true); this is measured behavior, not evidence that every platform behaves identically.

## Non-goals
No CLI, shared assembly, public API, schema, branch-reading or unrelated RepoFile change. No hard-link detection or protection from concurrent filesystem mutation between check and open. Do not claim those guarantees. No GUI.

## Design
Keep the initial lexical RepoFile.IsInside check before branch lookup. Preserve request-branch, task-branch, then working-tree precedence. Git blob reads do not traverse working-tree links: apply physical resolution only inside FromWorkingTree before File.Exists/read, never as a condition for accepting a blob already read from Git.

Add internal static SpecPath in src/Muthur.Server/Services/SpecPath.cs, server-only. Resolve(string absolute) returns fully resolved absolute path or null on an unresolvable path. Resolve both the project root and candidate. Reuse RepoFile.IsInside for OS-specific comparison and boundary. Null root/candidate throws Fail.Rule("spec_unreadable", "The spec location could not be determined."); resolved escape throws existing spec_outside_repository with existing message. Resolve before File.Exists so missing leaves below outward links are refused. Open the resolved candidate path. Existing ordinary missing-file, heading, size, needs declaration and state/ledger behavior stays unchanged.

Resolution algorithm: walk normalized absolute path component by component from its volume root. Inspect each candidate with File.GetAttributes. FileNotFoundException/DirectoryNotFoundException means append the remaining normalized suffix and return (missing files remain spec_missing unless an earlier link escaped). Any other IOException/UnauthorizedAccessException or invalid-path exception (ArgumentException/NotSupportedException) returns null. For FileAttributes.ReparsePoint, use File.ResolveLinkTarget(candidate, false); null is unresolvable. Recursively resolve its absolute FullName from the volume root, so ancestors of link targets are also checked; continue original suffix from that resolved target. Share a budget of 64 followed links across this resolution; exceed it => null. Do not use File.Exists/Directory.Exists as permission-denial detection. Non-link components continue directly. Catch expected filesystem/path failures; do not swallow cancellation or arbitrary bugs. Root/candidate resolutions each get a fresh budget. Document T-57 origin, target-ancestor distinction, hard-link and race limitations briefly.
