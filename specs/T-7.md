## Design

### Configuration and execution

Add `Dictionary<string, CensusCheckOptions> CensusChecks` (empty by default) to MuthurOptions. CensusCheckOptions has FileName (string), Arguments (List<string>, empty default), WorkingDirectory (string), TimeoutSeconds (int, default 30). Configured source is `census:<check-key>`; key must match `[a-z0-9][a-z0-9-]{0,63}` and resolve exactly to a configured entry. One source represents one check. FileName must be nonblank, working directory an existing absolute directory, args nonnull with no null entries, timeout 1..60 inclusive. Invalid/unknown configuration fails that poll, not hub startup. Configuration is local hub configuration under Muthur:CensusChecks, not command text in source locations or inbound. Founder uses existing project --ingest registration. No default check is enabled. Config changes take effect on restart under existing options binding.

Register CensusSource : IInboundSource, Scheme `census`. Fetch validates config and stored cursor BEFORE executing. Use a separate injectable ICensusCommandRunner/CensusCommandRunner in Server/Services/CensusCommandRunner.cs (do not alter shared IProcessRunner signature). Runner takes configured executable, literal argument list, cwd, timeout and cancellation; returns ProcessResult. Use ProcessStartInfo ArgumentList, UseShellExecute=false, CreateNoWindow=true, UTF-8 streams, close stdin. Do not concatenate a shell command. Shell scripts work by explicitly configuring pwsh and -File (or sh and script argument). Remove MUTHUR_AGENT, MUTHUR_TOKEN and Muthur__DiscordBotToken from child environment. This is trusted operator code running as the existing hub user, not a sandbox; document that scripts must be read-only, not invoke models, and must not perform outbound actions.

Bound TOTAL execution including draining redirected streams to configured timeout. Bound stdout and stderr individually to 1,048,576 characters while reading (not only after collecting unlimited output); exceed => kill tree, await/reap child and drains, return nonzero. Timeout => kill tree and clean up, code 124; startup failure => 127; caller cancellation cleans up and rethrows OperationCanceledException. Do not leave descendants behind on failure. Error messages exposed by adapter are safe fixed categories plus exit code; never expose process stdout/stderr, command arguments or raw exception text. Nonzero exit is failure even when stdout is valid. Pass success stderr through no logs/ledger. Probe validates configuration and executable resolution (absolute existing file, or PATH lookup) WITHOUT executing the check or altering cursor. LastError from failed polls still makes doctor fail; successful zero-findings poll clears it.

### Output and lifecycle

stdout is a complete JSON array snapshot, `[]` for success with no active findings. Whitespace-only, wrong shape/type, duplicate fields, unknown fields, duplicate IDs, malformed JSON => fail whole snapshot with safe InvalidOperationException, no partial ingest or cursor movement. Max 1,000 findings. Each object has required `id`, `title` and optional `body`, `url`. id matches `[a-zA-Z0-9][a-zA-Z0-9._-]{0,127}`; case-sensitive. title is nonblank <=500 chars; body omitted defaults empty, provided must be string <=16,000 chars; url omitted defaults null, provided must be string <=2,048 chars and absolute HTTP(S). title/id required strings; reject nulls. Fields are case-sensitive. Findings are inert text, never instructions or command input. Author on IncomingItem is `census:<check-key>`.

Persist cursor JSON version 1: `{ "version":1, "next":1, "active":{} }` initially, active maps finding id to positive incident sequence. For each validated snapshot, process IDs in ordinal sorted order. Still-active id reuses sequence; new id takes next and increments it (checked long arithmetic). Cursor after success contains only currently active IDs, preserving next forever. Validate stored cursor structure, version, IDs, positive unique sequences and next > all active sequences; malformed cursor fails safely without executing. Serialize compactly with System.Text.Json, no new HTTP DTO/AOT registrations needed for server-internal cursor.

ExternalId is `<check-key>/<id>/<sequence>` invariant decimal. Same active ID with changed title/body/url stays same incident: preserve existing inbound snapshot (existing StoreAsync behavior), do not duplicate or reopen converted/dismissed inbound. A successful snapshot omitting an ID resolves it only for recurrence tracking; do not auto-close tasks or inbound. Reappearance after a successful absence gets a fresh sequence and inbound item. Failure or hub downtime NEVER counts as resolution. Restart resumes cursor. Removing/readding or editing a check under the same key preserves identity and state; renaming key explicitly creates a new source/identity and may repeat findings, documented. Checks should retain stable IDs; changing text must not change IDs. Incidents entirely between polls cannot be observed; document this limit. Distinct sources have independent cursors and inbound namespaces.

Keep cursor + inbound writes atomic in existing ledger transaction. In that successful transaction, for census sources only, record `census.completed` with `{ source, findings, newItems }` counts (findings = fetched Items.Count, newItems = created.Count). No finding body in this event. This supplies evidence of zero-result runs over time as well as failures. Existing ingest.failing/recovered and doctor behavior remains. No new event on a failed snapshot beyond existing failure handling.
