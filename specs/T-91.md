# T-91 — XML documentation diagnostics policy

> Frozen spec. Stop and report contradictions; do not improvise policy.

## Goal
Establish a reproducible current warning inventory and an explicit proposed policy for stranded or duplicate XML summaries before changing build enforcement. Deliver evidence and a recommendation, not solution-wide enforcement.

## Context
Base main is 6c99654777c7edf9108e9653d3d3a6c3f747a7ce. T-70 has landed. Directory.Build.props treats warnings as errors and intentionally does not require documentation for every public member. CLAUDE.md says XML comments should add information. Do not assume GenerateDocumentationFile diagnoses duplicate summaries: measure it. Compiler diagnostics cannot establish whether prose describes the correct declaration.

## Non-goals
No product source, project files, package references, build defaults, CI, or existing comments change. No broad documentation cleanup. No hub startup or installed CLI tests are needed for this offline policy artifact. No new analyzer dependency.

## Design
Create docs/xml-documentation-policy.md and scripts/test-xml-documentation-policy.ps1 only (besides this spec). The script is an offline, deterministic evidence generator. It builds the solution serially with build servers disabled, captures logs under a caller-supplied OutputDirectory (default artifacts/xml-documentation-policy), fails on unexpected command failure, and emits a compact machine-readable inventory JSON. Use child dotnet commands; do not persist changed environment, global configuration, or processes. All subprocess waits must have a finite timeout and kill the child tree on expiry. No hub calls.

Inventory modes: baseline Rebuild; Rebuild with GenerateDocumentationFile=true and TreatWarningsAsErrors=false; Rebuild with GenerateDocumentationFile=true and NoWarn=1591 (warnings-as-errors retained). Record each exit and deduplicate compiler diagnostics by project/file/line/column/code/message rather than counting repeated MSBuild summary lines. Report counts by project and diagnostic code, including zeroes. Preserve raw logs. Do not mislabel environmental failures as diagnostics. Record SDK and actual source HEAD.

Generate a tiny temporary SDK C# library outside solution compilation inputs. Exercise separately: one valid summary, two adjacent summary tags on a declaration, a documentation comment stranded at end of a class, and a single well-formed summary with semantically incorrect text on a declaration. Run each with documentation generation false and true, suppress only 1591, retain warnings-as-errors. Capture diagnostic IDs, exit status and expected behavior. Distinguish a syntactically stranded comment from a semantically misplaced comment and multiple top-level summary elements from nested summary tags. Clean temporary fixture directories in finally, preserving logs and result JSON. A duplicate fixture that compiles is an informative result, not a failed script.

Report structure: exact baseline SHA/SDK/date and commands; warning inventory table; fixture result table; limits of compiler coverage; comparison of (a) unchanged compiler settings, (b) GenerateDocumentationFile with only CS1591 suppressed, (c) focused source-analysis rule; explicit recommendation; follow-up acceptance criteria.

Proposed policy to document: preserve existing missing-documentation policy; do not enable documentation generation solely to prevent duplicate summaries unless the probe demonstrates that it does so. Prefer a future focused syntax-aware check for more than one direct summary element in one declaration's documentation, with invalid-placement compiler coverage evaluated separately. Do not claim automatic semantic/provenance detection. Scope future check to tracked hand-written src/tests C#; exclude generated files, bin/obj and fixtures. Treat attached multiple documentation trivia carefully; specify cases to test and avoid regex-only enforcement. State that this task does not activate enforcement and future implementation needs its own reviewed task. If empirical results contradict this proposal, stop and report to orchestrator.
