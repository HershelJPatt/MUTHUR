# T-65 — KitCommands.Unwritable carries two `<summary>` tags, one left from T-56's rename

> Frozen spec. An implementer completes this without making design decisions.
> If something here is wrong or missing, the implementer stops and reports; they do not improvise.

## Goal

`KitCommands.Unwritable` is preceded by two `<summary>` blocks. The first one is not about `Unwritable` at all:
it is `Collision`'s doc comment, stranded when T-56 inserted `Unwritable` into the space above `Collision` and
moved `Collision` down the file without its comment. Today the second-most-load-bearing rule in the manifest
validator (`Collision`, rule 20) is undocumented, and the function that refuses an unwritable repository is
introduced by a paragraph about last-one-wins path collisions. After this task each function carries the
comment that was written for it, and a reader of `Unwritable` is not told about rule 20 first.

This is a documentation-only change. No behaviour changes, no test changes.

## Context

- File: `src/Muthur.Cli/Commands/KitCommands.cs`. Nothing else is touched.
- The two blocks sit at lines **268–272** and **273–277**, both immediately above
  `private static string? Unwritable(...)` at line **278**.
- `private static (Destination A, Destination B)? Collision(List<Destination> destinations)` is at line
  **353** and has **no** doc comment.
- The provenance is not a guess. In `73b81a0` ("T-8: rules 19-21 and a last-resort guard around the manifest
  reader") the stranded block sat directly above `Collision`, which then had the signature
  `private static (int A, int B)? Collision(List<string> destinations)`. T-56's commits (`a105ee1`, `567d08a`,
  `1a8248a`) introduced `Unwritable` and re-typed `Collision` over `Destination`; the comment stayed where it
  was and `Collision` moved.
- CLAUDE.md: "XML doc comments only where they say something the name doesn't." Both blocks pass that test —
  which is why this task moves one rather than deleting it.
- Warnings are errors (`Directory.Build.props`, `TreatWarningsAsErrors`). The duplicate does not currently warn,
  because no project in the solution sets `GenerateDocumentationFile`. That is why this survived: nothing but a
  reader can catch it.

  task's call to make.

## Design

One edit, in two halves.

**Remove** from above `Unwritable` (current lines 268–272), leaving the `Unwritable` block (273–277) as that
function's only doc comment:

```
    /// <summary>
    /// Rule 20, and the first rule here that reads the manifest as a whole: each entry below is valid on its
    /// own, and it is the pair that cannot be honoured. Two entries naming the same path are not a collision —
    /// that is last-one-wins, which the format has always allowed — so only file-versus-directory counts.
    /// </summary>
```

**Insert** those same five lines, verbatim and with the same four-space indentation, immediately above
`private static (Destination A, Destination B)? Collision(List<Destination> destinations)`, with no blank line
between the comment and the signature — the style every other documented member in this file uses.

The blank line that currently separates `InstallerFiles` (line 266) from the comment block stays as the single
blank line between `InstallerFiles` and `Unwritable`'s own `/// <summary>`. The blank line above `Collision` stays
above the newly inserted comment. Net effect on the file: five lines move down; the line count is unchanged.

Nothing else in the file is edited. The diff should be exactly one deletion hunk of five lines and one insertion
hunk of five lines.
