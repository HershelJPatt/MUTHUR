# T-107 — Repeatable verification and verified preparation reuse

> Frozen spec revision 3. Resumed on integrated main 2e51fd4 (including landed T-117, T-100 and T-101). Original main df3f929 remains an ancestor. Stop and report missing design decisions.

## Goal
Provide a deterministic runner-side verification command, complete evidence, and a conservative content-addressed cache of MUTHUR installation files. Reuse never substitutes for fresh tests, installed smoke, or independent validation.

## Context
T-95 and T-99 are landed; current main includes run/dispatch identity and immutable validation subjects. Use Muthur.Launch IProcessRunner and ProcessRunner for child processes, CLI System.CommandLine and source-generated JSON patterns. The hub stays unchanged and performs no execution/model calls. Follow CLAUDE.md, installed-only scratch rules, full-suite requirements. T-67/T-88/T-97 and the open human Claude authentication decision remain untouched. One implementer at a time; no local implementer, new permissions, accounts or budget changes.

## Non-goals
Universal workflow engine, arbitrary shell recipes, remote/shared cache trust, caching tests or approvals, live installs, changing validator gates, model calls, UI, credential/database reuse.

## Design
### Public command and project recipe
Add `muthur verify run --repo <path> --ref <commit-or-local-ref> --spec <repo-relative-path> --recipe muthur --output <new-directory> --cache <directory> [--task T-n] [--parent-run <id>] [--subject <guid>] [--timeout-minutes 60] [--no-cache]` as a local command requiring no hub. All of repo/ref/spec/output/cache required. Resolve ref once to full commit. Validate subject syntax, but label task/parent-run/subject as caller-provided references, not hub-verified approval. Generate unique run GUID always. Return machine JSON including runId, status, evidencePath, cache status; exit 0 success, 2 invalid input, 1 execution/cleanup failure, 124 timeout, 130 cancellation. On external hard kill an initial persisted running bundle must never read as success.
Add `verification` to muthur.project.json without altering build/test values. Schema version 1, named recipe `muthur`, explicit committed inputs (`**` meaning entire Git tree plus frozen spec and recipe), preparation command `pwsh -NoProfile -File scripts/install.ps1 -Destination {install}`, build `dotnet build`, test `dotnet test -v n`, fresh installed command `{install}/muthur.exe up`, readiness HTTP `/health` ONLY if actual endpoint exists (otherwise `/`), `{install}/muthur.exe status`, `{install}/muthur.exe down`; expected outputs muthur.exe, server/Muthur.Server.dll, kit, provenance file if installer emits one. This first version supports only the exact MUTHUR recipe shape/commands; validate unsupported versions/commands/paths before execution. Array arguments, never eval or concatenated shell commands. Document all schema fields and fixed placeholders. Recipe timeout may only shorten command timeout. Do not silently run defaults for malformed or missing config.
Implementation: new VerificationRunner, VerificationCache and DTO/source-generated JSON context in Muthur.Launch (split files as needed), VerificationCommands in CLI and registration in Program. Do not put execution in Server or Contracts. Reuse existing seams and support fake IProcessRunner plus deterministic test hooks for time/cancellation/file barriers.

### Isolation, execution and cleanup
Resolve canonical repository/common Git directory identity, verify spec regular committed file, read exact recipe and spec at captured commit. Create one detached Git worktree inside unique runner scratch child of output, check exact clean HEAD before commands; refuse output/cache intersecting repo, each other, or existing output, and reject reparse/symlink roots/ancestors used for writable paths. Output/cache may be under repo's ignored artifacts directory ONLY if they are outside the created checkout and each other; no traversal allowed in configured paths. Source changes after capture cannot alter run.
Each run gets unique MUTHUR_HOME, temporary directories and loopback port. Scrub MUTHUR_TOKEN/AGENT/URL/HOME plus common cloud/token credentials from child environment; use an explicit minimal environment allowlist needed for local .NET/PowerShell/Native AOT toolchain (PATH/SystemRoot/COMSPEC/PATHEXT/TEMP/TMP/USERPROFILE/LOCALAPPDATA/ProgramFiles/ProgramFiles(x86)/DOTNET_ROOT/NUGET_PACKAGES and VS/VC/Windows SDK toolchain variables). Override HOME, USERPROFILE, DOTNET_CLI_HOME, TEMP/TMP, MUTHUR_HOME and URL to run-owned scratch locations. No arbitrary inherited settings. Do not cache homes, NuGet directories, mutable databases, logs, or scratch. Toolchain probing/build/publish must work under these controls; report any missing prerequisite rather than widening permissions.
Sequence: initial running evidence; provenance/key probes; dotnet build; full dotnet test -v n; restore verified installation cache or run preparation; installed up, bounded HTTP readiness, status, down; verify process stopped; cleanup; only then publish cache success entry and final successful evidence. Preserve actionable stdout/stderr per command in output, redact credential patterns where relevant; never include arbitrary environment dumps. Tests always run even on cache hit; preparation may be reused only. Independently required task-specific checks remain external to this general smoke and are documented as required by their specs.
Global timeout/cancellation applies to all commands. Fix ProcessRunner cancellation/timeout to kill process tree, await exit/drain within a bounded budget; retain partial stdout/stderr and stable timeout failure. Do not break existing caller cancellation semantics. Installed `up` detaches a server: runner must capture its PID/start identity from scratch hub state/status, or launch server directly under a tracked process if required to ensure ownership; never kill by name or an unverified reused PID. Always down in finally with bounded independent cleanup token, confirm exit, then remove only verified owned scratch/worktree. Cleanup failure forces failed evidence and no new success cache. Register run ownership metadata (paths/process ID + start identity) before dangerous stages. Provide `muthur verify cleanup --output <directory>` to recover a hard-interrupted run: validate version/ownership/root boundaries, refuse active runner PID/start identity, stop only recorded owned processes, remove owned worktree/scratch, mark abandoned evidence interrupted. Never delete output evidence or another run. Cleanup idempotent; malformed ownership refuses with instructions, no guessed deletion. Cache locks must be OS file locks released on process death.

### Provenance and cache
Key = SHA256 of canonical versioned input manifest: canonical repository identity, full commit and tree ID, exact spec SHA256, entire recipe SHA256, runner schema/build identity, OS/architecture, dotnet --info, pwsh/git versions and resolved executable content hashes, relevant allowed toolchain environment values (hash values to avoid leaking user paths), plus declared committed inputs. No unknown probe values: fail closed to cache miss/disabled with reason; tests still execute. Include SDK/VC/toolchain executable identity relevant to publish; if identity cannot be established reliably disable reuse. Conservative misses acceptable; never claim reuse without complete identity. Full commit intentionally means any source/spec/recipe change misses. Build configuration is explicit in recipe/manifest; prohibit ambient build overrides.
Cache supports only regular immutable installation file trees under `install`, all relative paths normalized and validated, no symlinks/reparse points, rooted paths, traversal, case-collisions, credentials/home/db file types. Manifest lists exact files, size and SHA256, key/input manifest, producing run ID/commit/spec/recipe, completion timestamp and success status. Verify manifest digest and every file on each read; reject missing/extra/tampered/partial/unknown-schema/input-mismatch entries, record rejection reason and rebuild. Hashes protect accidental corruption, not malicious same-user rewriting; document local-user trust boundary. Copy to fresh run install and verify destination again, never execute directly in cache. Acquire per-key exclusive bounded lock for reader/writer/eviction safety, staging unique directory then atomic directory rename only after success, never overwrite in place. Concurrent same key requests may duplicate work but publish only a complete entry. Failed tests, killed commands, failed smoke or cleanup cannot publish success entry. Existing valid entry may remain after a later failure but evidence status must be failed and fresh checks visible. Evict under locks, max 3 completed entries by completion age, skip busy entries; incomplete staging from dead writers removed only under matching key lock with ownership check. No live execution under cache. `--no-cache` neither reads nor publishes; evidence records bypass.
Evidence bundle schema v1: run references, canonical repository/full commit/tree, spec path/digest, recipe name/version/digest/full command definitions, input manifest/key/toolchain, start/end UTC, each stage argv/cwd-relative/environment policy/exit/status/timestamps/duration/log refs, cache hit/miss/rejected/bypassed and producer provenance, output file digests, testsExecuted=true only when actually started/completed (separate flags), cleanup details, final status. Write initial and stage updates atomically. Successful bundle requires every required stage and cleanup success. Evidence is an observation, never validation approval; validators retain their checks and judgment. Evidence mutable file is not automatically attached to T-99 approval.
