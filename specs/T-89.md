# T-89 — Respect the harness-owned worktree assignment

> Frozen spec. Stop and report if this contract cannot be implemented without further decisions.

## Goal
Make delegation executable when native Claude isolation selects a different worktree than an orchestrator prepared. The procedures must never promise that a prompt assigns a filesystem path. Use the existing worker launcher for deterministic branch assignment; native subagents use and report their actual isolated tree.

## Context
T-73 is landed on main. It already guards base branch/dispatch SHA and recovery; preserve all those guards. kit/core/orchestrate.md step 4 still describes assigning a worktree/branch without distinguishing base from output. kit/core/implementer.md requires the supplied path, while Claude agent definitions enable isolation: worktree. kit/claude/skills/muthur-orchestrate.md describes native dispatch. WorkerCommands already creates a fresh worktree via --base and --branch and WorkerLauncher launches the process in request.WorkingDirectory. No new harness capability is required or claimed.

## Non-goals
No harness permission expansion, disabling isolation, EnterWorktree approval bypass, path adoption CLI, launcher/API/schema changes, or change to T-73 history recovery. Do not modify generated .claude files. No local workers or live model tests.

## Design
1. Define two dispatch modes consistently across core and Claude procedures: native isolation allocates the path and output branch; muthur worker run allocates a fresh worktree and accepts an explicit new output branch with --branch. Neither accepts adoption of an already-prepared worktree. The frozen base branch is distinct from the output branch.
2. Prefer worker run when deterministic output branch placement is required. Supply a concrete command pattern using --tier implementer --spec specs/T-n.md --unit "Unit A" --task T-n --base task/T-n-<slug> --branch task/T-n-unit-a --note containing base branch, full dispatch SHA, and default branch. The output branch must not already exist; do not pre-create its worktree. The launcher report supplies the actual path/branch. For specialist work use mastermind tier under existing rules.
3. Native Agent dispatch passes the relative spec path, unit, base branch/full SHA/default branch and checks, not a prepared absolute worktree as an assignment. Both Claude agent definitions retain isolation: worktree. They must discover git rev-parse --show-toplevel and git branch --show-current, stay there and report both. Do not call EnterWorktree or write through a prepared sibling path to repair assignment. A contradictory explicit path assignment returns STATUS: blocked with expected/actual root and branch, before writes, so orchestrator can redispatch via worker run. Do not copy uncommitted output by hand between trees as normal integration.
4. Core implementer distinguishes an explicit launcher-provided tree from native harness allocation: explicit root mismatch blocks; native root is the actual isolated root. Keep the existing T-73 base/SHA/clean-tree guards intact and applicable to both. Add WORKTREE: <absolute actual root> to the report format; retain BRANCH. Orchestrator checks reported root and output branch before integrating committed branch output into task branch only.
5. Add focused kit installation regression tests which install the Claude kit into a temporary repository using existing test infrastructure and verify rendered orchestrate plus both agent definitions carry the mode distinction, no prepared-path migration instruction, isolation retained, and WORKTREE reporting. Prefer semantic assertions over full prose snapshots. No real paid model invocation is needed.
