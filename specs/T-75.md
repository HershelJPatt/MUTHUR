## Design
Create docs/SPEC-BRANCH-HINT.md describing the decision and source request. Branch remains optional. A missing file or nonexistent hinted branch falls through to the task branch (if set and distinct), then the project repository working tree. A source containing content is authoritative for validation: invalid content must fail rather than searching for a valid replacement. Omitted CLI branch uses inferred checkout ref where available; omitted API Branch is null. Default-branch specs remain supported by the working-tree fallback or explicit default-branch hint. Working-tree content need not be committed for attachment; orchestrators must still commit frozen specs before delegation. Existing spec_missing diagnostics and all existing guards remain. Explain that T-68's implementer base incidents do not justify breaking this attachment contract and that future strict provenance requires a concrete problem and migration proposal.
