## Design

1. Add scripts/browser-capability.ps1, scripts/browser-capability.cjs, scripts/browser-smoke.cjs and tests/browser-capability.test.cjs. PowerShell is the bounded entry point even when Node is missing. Parameters: -NodePath (default node), -PlaywrightPath (optional absolute module directory), -BrowserPath (optional absolute installed executable), -TimeoutSeconds (default 30, valid 1..120). Optional -Url and -AgentName run the smoke after capability succeeds. Probe emits one JSON object and exit 0 for available, exit 2 for unavailable; unexpected errors are also nonzero and actionable. JSON separates connector (status unknown: caller must inspect its connector), headless (available/unavailable, reason, selected node/module/browser paths), and http (render-only; never interactive). No connector probe is invented. Node absent, module missing, executable missing and launch denied/timeout are distinct reasons. Explicit invalid overrides never silently fall back.
2. Discover only installed tooling: resolve node from PATH, resolve playwright or playwright-core from the script/repository using Node resolution, allow an explicit module path (including an already installed external path); discover standard Windows Chrome/Edge paths or Playwright's already-installed chromium executable. Do not recursively scan disks or invoke package managers. Launch headless with normal browser sandbox/security defaults; never add --no-sandbox or ignore certificate errors. Use a fresh nonpersistent browser context, local data URL button with a click and changed-text assertion to prove capability, close context/browser in finally. Parent PowerShell enforces the total deadline and kills its own process tree on timeout; never terminate unrelated browsers. All argument handling uses argument arrays and supports paths with spaces. No shell concatenation of paths.
3. Smoke mode requires explicit loopback http URL with non-default port (reject 7420, credentials, non-loopback hosts, redirects to other origins); require AgentName. Against an already running isolated scratch installed hub, visit /console, wait for the Blazor connection, fill agent-name, agent-harness=fixture, agent-model=fixture, agent-tier=mastermind, click Register, assert successful registration via the scratch /api/agents response and rendered UI or success feedback. Fail on page errors. The runner does not launch a hub or use live identity/token. The caller owns starting/stopping scratch with per-child MUTHUR_HOME/MUTHUR_URL. Always close owned browser processes, including failures. Print concrete interaction evidence separately from probe JSON if smoke requested. Inspect actual routes and feedback in Console.razor to use exact selectors/API shape.
4. Add one recognized need: headless-browser (case-insensitive after existing markup trimming). TaskService.SpecNeeds skips only this exact need and continues scanning all lines for other needs; every other need remains attended, in any order. Do not clear existing/manual attended reasons when replacing a spec. Update comments/reason text to avoid claiming all unattended sessions lack browsers. Tests cover marker alone, markup/case, mixed declarations both orders, unknown declarations and retained attended reason. No conductor changes: headless is explicitly unattended-capable; its actual prerequisites must be preflighted before builds and before implementation submission.
5. Update kit/core/orchestrate.md, kit/core/validate.md, kit/core/spec-template.md, specs/_TEMPLATE.md, kit/briefs/validator.md, briefs/validator.md, and tests/Muthur.Cli.Tests/KitInstallTests.cs. Teach three distinct paths: HTTP-only assertions, connector-driven UI, installed headless interaction. Connector unavailable means try explicit headless probe under existing permissions. Headless spec declares needs: headless-browser and exact probe/tool paths/interaction commands; needs: browser retains attended semantics for compatibility/human visual needs. Run prerequisite probe before expensive validation build; record exact missing tool/permission evidence and blocked verdict when neither permitted path works. Never silently substitute HTML, install tooling, expand permissions, or start more harness sessions; preserve shared two-session ceiling. Probe success is not proof of product behavior. Keep kit template and checked-in template byte-identical. Explain scripts are this repository's supported runner; generic kit consumers supply their own equivalent bounded runner.
