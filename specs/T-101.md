## Design
### Storage and contracts
Use an additive versioned JSON document in existing Meta table, key task.units/<numeric-task-id>; all changes plus task.unit_* events in one Ledger.MutateAsync transaction. This avoids requiring reconstruction or migrations for historical tasks. Define DTOs in Contracts/TaskUnits.cs, register all crossing types in MuthurJsonContext. The graph document has schemaVersion=1, revision (starts 1, increases per accepted mutation), specPath, specBlob (full Git blob ID), integrationBranch (named non-default local branch), units. Each unit has id (case-sensitive ASCII [a-z][a-z0-9-]{0,39}), dependencies (unit IDs), requiredChecks (unique nonempty names), current attempt (optional), invalidationReason (optional). Max 50 units, 20 dependencies/checks per unit, names <=100 chars. Validate DAG, duplicate IDs, unknown/self dependencies atomically. Stable identity is (taskId,specBlob,unitId).

Attempt contains attemptId (caller UUID), baseCommit, outputBranch, outputCommit (nullable), reportedState (running/done/failed/recovered), reviewState (pending/accepted/rejected), integrationCommit (nullable), checks [{name,exitCode,evidencePath,evidenceCommit}], reviewEvidencePath/reviewEvidenceCommit, nextAction (<=500 chars), dependencyAttempts map, timestamps and reporting actor. Full state is available via GET; events retain older attempts/graphs. No automatic trust of reported done. Fields set by service transitions, never a caller-supplied whole state.

### Public surface
GET /api/v1/tasks/{id}/units -> complete current graph (null when absent), GET /api/v1/tasks/{id}/resume -> {taskId, graphRevision, latestDecisions, blockers, units, omittedUnits, evidenceRoute, nextAction}. Use existing DecisionContext and include open request IDs/kinds and task dependency IDs. Bounded resume: at most 20 unit rows, each with id, attemptId, reported/review/integration state, output branch/commit, nextAction, invalidation reason; clip long strings, bound entire rendered conductor unit context to 8000 chars, show omitted count and full units/task-show commands. No graph yields normal old task context, not an error.
POST /api/v1/tasks/{id}/units/define accepts {expectedRevision:0 for absent otherwise current, specBlob, integrationBranch, units:[{id,dependencies,requiredChecks}]}. specPath is task.SpecPath. Resolve integration branch and spec blob using Git in registered repo; require matching provided full blob and regular committed spec, non-default branch. Same spec cannot redefine unit IDs/dependencies/check requirements: exact definition replay is idempotent; changed definition requires a changed spec blob. Different spec creates fresh units and records invalidated prior graph in event, with explicit reason; do not carry prior completions across specs.
POST /api/v1/tasks/{id}/units/checkpoint accepts {expectedRevision, unitId, attemptId, action, baseCommit?, outputBranch?, outputCommit?, checks?, reviewEvidencePath?, reviewEvidenceCommit?, nextAction?, reason?}.
CLI: `muthur task units <id>` reads complete graph; `muthur task units <id> --define <json-file>` defines it; `muthur task checkpoint <id> --file <json-file>` posts transition; `muthur task resume <id>` reads packet. JSON files allow precise CAS inputs without many flags. Use AOT-safe existing HTTP/Output patterns. Document complete examples in docs/work-unit-checkpoints.md.

### Ownership, CAS and transitions
Mutations require current live task owner with unexpired claim and InProgress state; founder may perform them while InProgress. Anonymous/other agents rejected using existing Fail/Caller patterns. CAS graph expectedRevision mismatch => 409 checkpoint_conflict. Old attemptId cannot mutate a newer attempt => 409 stale_attempt. Validation/landing endpoints and criteria unchanged; no checkpoint action may call them. Reads remain compatible with existing read authorization.
Actions:
- start: UUID must be new (reject reuse from historical task.unit_started events); requires explicit pinned full baseCommit and named local outputBranch (branch may not exist yet), not default or integration branch. Base equals current integration branch HEAD; spec at base matches graph spec. Every dependency must be accepted and integrated with existing ancestry proof. Snapshot their attempt IDs. Store running/pending, clear old checks/integration. Replacing previous attempt requires nonempty reason. Invalidate transitive dependents (clear accepted review/integration, retain output evidence and reason); independent units unchanged. Record dispatched base/branch before worker launch.
- report: only matching current attempt, running or already reported; done when outputCommit supplied, failed otherwise with required reason. Verify supplied full commit exists, descends from base, and outputBranch points to it; done is still pending review. Identical replay is no-op. Conflicting report after accepted review must reject. No checks accepted here.
- reconcile: for current attempt, inspect current outputBranch without running a worker. If a newer commit descends from base and has matching spec, record outputCommit/recovered/pending; this handles commit-before-report. Never auto-accept. If commit equals dispatched base, keep running and nextAction to obtain output. Missing branch/commit, changed spec/base ancestry, changed dependency attempt, or missing evidence invalidate review/integration with reason; no deletion. If already accepted and all pinned proof still holds, preserve review and checks; do not erase them just because owner changed. Resolve integration by read-only ancestry: only if accepted output is ancestor of integration branch HEAD, record that head as integrationCommit (idempotently); otherwise retain accepted and nextAction=integrate. Existing integration marker must be cleared if ancestry no longer holds.
- verify: requires output previously reported/reconciled, current Git proof, dependency snapshots current, all required named checks exactly once and exitCode=0; each check proof uses a full evidenceCommit plus canonical relative regular-file evidencePath existing at that commit, evidenceCommit descendant of outputCommit. Review proof same requirements. The owner attests it reviewed diff and ran the named checks: evidence records are not executed or interpreted by hub. Verify stores accepted proof; nextAction=integrate unless current ancestry proves integration. A check failure or missing proof is refused, never accepted. Need not change outputBranch head after reporting: pinned output must remain reachable from outputBranch; rewritten branch invalidates. No passing a mere checkpoint-complete flag.
- invalidate: required reason; keep output/history but clear accepted review/integration/check acceptance for unit and transitive dependents, leave independent units intact; nextAction=redispatch.
- integrate: requires accepted current proof, output ancestor of integration branch head; stores integration head, nextAction=complete. Never performs git writes. Repeating same observation is idempotent; crash after merge before recording is handled by reconcile. Changed branch HEAD alone is not stale if dispatched base remains ancestor, spec unchanged and dependency assumptions unchanged; rewind/divergence fails. Check full commit IDs as hex SHA-1/SHA-256; branch/path validation disallows option/revision injection, traversal, symlink evidence/spec and absolute paths. All git calls argv-based, bounded, no arbitrary file access.
Before positive transitions, inspect current integration spec/base, output ancestry, dependency attempts and evidence existence. Never accept missing or stale artifacts. `resume` is advisory state (include explicit "run reconcile before reuse" for accepted units), not a proof execution endpoint. Reconcile performs probes and durably records invalidation; callers cannot confuse a stored accepted marker with current verification. Spec changed -> next action redefine graph; no silent reuse. Missing objects -> next action recover artifacts or redispatch.
